True Peak (dBTP) expliqué

Le sample peak (dBFS) ne voit que les échantillons. Le true-peak (dBTP) estime le maximum réel après reconstruction analogique et après encodage lossy. C'est la mesure qui évite le clipping sur les plateformes et les téléphones.

Sample peak vs true peak

Un limiteur qui affiche -0,1 dBFS sample peak peut laisser passer des inter-sample peaks au-dessus de 0 dBFS. Ces overs n'existent pas dans le fichier PCM, mais apparaissent après le filtre de reconstruction du DAC ou après un encodeur AAC/Opus/MP3.

Pourquoi les codecs créent des overs

Les encodeurs lossy remodèlent le signal. Même un master « clean » à -0,3 dBFS sample peut dépasser 0 dBTP après encodage. D'où la recommandation quasi universelle : laisser -1,0 dBTP de marge, souvent -1,5 dBTP pour plus de sécurité.

Cibles true-peak sûres

  • Streaming (Spotify, YouTube, etc.) : ≤ -1,0 dBTP
  • Broadcast EBU R128 : souvent ≤ -1,0 dBTP (parfois -2 selon le cahier des charges)
  • TikTok / Shorts / Reels : ≤ -1,0 dBTP recommandé malgré des niveaux short-term plus élevés

Comment JSM le mesure

Oversampling 4× conforme aux recommandations ITU pour estimer le true-peak. Affichage en dBTP aux côtés du LUFS intégré et du LRA.
